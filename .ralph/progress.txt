## Codebase Patterns

- `crates/roku-agent-runtime/src/runtime.rs::runtime_loop_boundary_suite_covers_contract_edges` is the authority for direct-loop boundary regressions; when one case matters for contract clarity, assert trace fields directly in that suite instead of relying only on shared regression helpers.
- `crates/roku-runtime-service/src/runtime_loop_lifecycle.rs` owns direct-route terminal trace projection; when guarding pending-approval or success terminals, assert `runtime_loop_trace` step and `final_outcome` fields there instead of inferring from task state alone.
- `crates/roku-runtime-service/src/runtime_loop_lifecycle.rs` also owns explicit `AwaitingUser` trace projection for direct-route pauses; keep stale freeform discard checks in `crates/roku-runtime-service/src/tests.rs` focused on `assess_awaiting_user_resume` reasons instead of only response/status side effects.
- `crates/roku-runtime-service/src/memory_context.rs::attach_visible_resources` owns direct-route visible resource projection into `ContextBundle`; keep those assertions in `crates/roku-runtime-service/src/tests.rs` with explicit `RouteDecisionResult::Direct` inputs instead of mixing resource checks into lifecycle trace tests.
- `crates/roku-agent-runtime/src/runtime.rs::assess_awaiting_user_resume` owns ask-user resume outcomes by `AskUserResumeContract`; freeform pause tests should assert both the `NoAutomaticResume` contract and the exact fresh-intake rejection reason there instead of relying on `AskUserPayload::can_resume` alone.
- `crates/roku-agent-runtime/src/runtime.rs::assess_awaiting_user_resume` also owns candidate-selection resume outcomes; candidate pause tests should assert both the `CandidateSelection` contract and the exact grounded-choice assessment there instead of stopping at `AskUserPayload::can_resume`.
- `crates/roku-agent-runtime/src/runtime.rs::assess_missing_required_input_resume` owns the router-backed missing-input resume gate; missing-input pause tests should assert both `AskUserResumeContract::MissingRequiredInput` and the exact returned `AwaitingUserResumeAssessment`, not only prompt substrings.
- `crates/roku-runtime-service/src/runtime_loop_recovery.rs` is the owner for generic pending-loop snapshot lifecycle; future resume or durability work should inject `PendingLoopSnapshotStore` there instead of reintroducing `RuntimeService`-local map truth.
- `crates/roku-runtime-service/src/tests.rs` reconstruction coverage should assert the resumed experiment strategy `runtime_loop_resume` and the shared `PendingLoopSnapshotStore` cleanup sequence explicitly; terminal resumes currently delete the same session snapshot once at intake and once again during terminal sync.
- `crates/roku-runtime-service/src/runtime_loop_owner.rs` owns intake-time direct runtime loop branching across planning-hint compatibility fallback, pending-loop resume, and fresh route dispatch; future lifecycle changes should land there instead of expanding `RuntimeService::execute_with_mode` again.
